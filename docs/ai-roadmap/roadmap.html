Nummoria  /  from LLM wrapper to AI system

A phased roadmap for the three priorities

Eleven weeks, solo and part-time, sequenced so each phase leaves behind a measurable artifact and a resume bullet you can defend in an interview. The product surface barely changes — the engineering underneath it does.

Priority ① Extraction & categorization pipeline

Sequencing logic

Why this order

The full eval harness (③) is not phase one, but its two hardest-to-retrofit pieces — request tracing and a labeled golden set — are. Those come first, in P0, because bolting instrumentation onto a running system later is miserable.

Extraction (①) precedes the agent (②) because the agent's whole value proposition — never inventing a number — depends on a clean, typed transaction store to ground against. Learned categorization comes after extraction because it needs the labeled corpus that the extraction correction UI produces. The agent comes last because it consumes everything built before it.

P1
Extraction pipeline
Effort
~3 weeks (wk 2–5)
Depends on
P0 tail
Priority
①

Turn document ingest from a single parse call into a layered pipeline with a cost story and a measured accuracy story.

Workstreams

  • Deterministic layer: format detection plus per-format CSV / PDF parsers, extending the existing ingest code
  • Model extraction with structured output (function calling / constrained JSON) and per-field confidence scores
  • Two-tier cascade: deterministic parser → large model, escalating only when parser confidence falls below threshold (a small-model middle tier is a later add)
  • Human-in-the-loop correction UI; each correction is written back as a labeled training example
  • Field-level precision / recall / F1 on the P0 eval set, broken out by bank layout

Exit criteria

  • Field-level F1 ≥ 0.93 aggregate, with a per-layout breakdown
  • Cost per document and cascade escalation rate reported on the dashboard
  • ≥ 15 distinct layouts represented in the eval set
Resume claim unlocked

Built a multimodal bank-statement extraction pipeline (PDF / image / CSV) with a confidence-gated cascade — ~95% field-level F1 across 15+ layouts, with the deterministic tier handling the majority of documents at near-zero model cost.

Effort
~2 weeks (wk 6–8)
Depends on
P1, P2
Priority
①

Replace an LLM call with a real trained model — the clearest signal that you can do classical ML, not just prompt engineering.

Workstreams

  • Baseline: measure the current LLM zero-shot categorizer on accuracy, latency and cost
  • Train one classifier on merchant strings — sentence embeddings + gradient boosting (commit to this; skip the transformer bake-off for now)
  • Head-to-head benchmark across all three axes on a held-out set
  • Personalization: user corrections shift predictions via a per-user few-shot / prior layer

Exit criteria

  • Learned model beats the LLM baseline on at least two of three axes
  • Large model retained only to generate training labels
  • Personalization measurably improves per-user accuracy
Resume claim unlocked

Replaced an LLM transaction categorizer with a distilled transformer: +6 pts accuracy, ~40× cheaper, 210 ms → 9 ms p95; the large model was kept only for training-label generation.

P4
Agentic analyst + grounding
Effort
~4 weeks (wk 7–11)
Depends on
P0, P2 (P1, P3 feed it)
Priority
②

The flagship demo: an agent that reasons over the user's finances and cites a source for every figure it states.

Workstreams

  • Semantic layer: natural language → structured query over the transaction store (text-to-analytics), not raw rows in context
  • Four tools: query_transactions, cashflow_forecast, detect_recurring, simulate_scenario (market-data and cohort tools are a later add)
  • Planner / executor loop with tool-selection evals and full-trajectory evals
  • Numeric-grounding guard: a post-generation pass rejects any number not traceable to a tool result
  • Retrieval over transaction summaries and a small knowledge base; answers cite specific transactions

Exit criteria

  • Zero fabricated figures across a 150-case eval; the prompt-only baseline is measured for contrast
  • Groundedness score meets target; trajectory eval pass rate reported
  • Every numeric answer links to its source rows in the UI
Resume claim unlocked

Designed a 4-tool financial analysis agent with a deterministic numeric-grounding guard — 0 fabricated figures across a 150-case eval versus a measured double-digit rate in the prompt-only baseline.

The tradeoff

What the compression costs

Eleven weeks instead of eighteen is bought with parallelism and narrower scope, not by cutting a phase. What shrinks:

Deliberately smaller in the 11-week track

  • Extraction covers ~15 bank layouts, not 30+; the cascade is two tiers, not three (no small-model middle).
  • Golden set lands near 100 cases, not 120+; the dashboard is functional, not polished.
  • Categorization commits to one model family (embeddings + GBM) instead of running a transformer bake-off.
  • The agent ships 4 tools, not 7 — market-data and cohort comparison come later.
  • Cost engineering (semantic cache, model router) is deferred entirely to a follow-up pass.

The core story is intact: every phase still ends in a measured artifact, and the numeric-grounding claim — the flagship — is untouched.

Discipline

Explicitly out of scope

Not in this roadmap — on purpose

  • Pre-training or full fine-tuning of a large model from scratch — distillation of a small model in P3 is the ceiling
  • Multi-tenant infra scaling, sharding, or a data-platform rebuild — unrelated to the AI-engineering story
  • New product surfaces that don't serve one of the three priorities
  • Chasing every model release — model upgrades are gated through the P2 eval harness like any other change
  • Reworking the mobile receipt OCR until P1's pipeline is stable and can absorb it

Effort ranges assume ~10–15 hours per week and shift with real data quality. All metric targets (F1, cost multiples, latency, fabrication rate) are goals to hit and report honestly — the defensible claim is the eval methodology and the measured before/after, whatever the final numbers are.
